# E0's platform probes

**The probes are retired** (the Owner, 2026-10-22, #7). Every item has been answered, and each run's link and measured values are on Kanon issue [#968](https://github.com/yedeya-labs/kanon/issues/968). The `probe-*.yml` workflows are gone from `.github/workflows/`, so the dispatch commands below no longer run: this file stays as the record of what was measured, how, and what was found. A probe's last version is in the history, at `c94276a` (`git show c94276a:.github/workflows/<its file>`).

Kanon's plan 0012 ("end-to-end tests in throwaway repositories, and a release gate on them") rests on eighteen platform assumptions. Its §12 lists them, and Kanon issue #968 asks for each to be measured here, in the test organisation, before the runner is built. Item 19, added after §12, measures one more: what doctor can see on the read-only token of plan 0012's `kanon` job (decision 23 (b)). The workflows `.github/workflows/probe-*.yml` measured the ones a workflow could. This file lists every item, with each probe's dispatch command, and the steps a person took for the rest.

## The rules every probe keeps

- **Dispatch only.** Each probe runs on `workflow_dispatch` and nothing else. Probe 12's called workflow runs on `workflow_call`, from probe 12 alone.
- **Keys stay in their environment.** A job reads an App's id and key only when it declares the environment that holds them (`e2e` or `e2e-report`), and passes them only to `actions/create-github-app-token`, pinned by full SHA. The token is masked by the action; every value derived from one is masked too. No probe prints or uploads a token or a key. No probe reads `e2e-model`.
- **Least permissions.** Every workflow sets `permissions: {}`. A job gets `actions: read` only where it reads a run's jobs or timing. Each App token asks for the permissions its probe needs, no more, except where the question is about the App's whole set (probe 09).
- **Throwaway repositories are deleted.** A probe that creates a repository names it `e2e-probe-NN-<run id>-<attempt>` and deletes it in an `always()` step, or an `always()` job, whatever happened before.
- **One fixed answer.** Each run writes a step summary table: the §12 item, its question, what was measured, and **PASS**, **FAIL**, **INCONCLUSIVE** or, for probe 09's and probe 19's lists, **MEASURED**. Post that table with the run's link on #968.

## The answers, as measured

Every item has been answered on Kanon issue [#968](https://github.com/yedeya-labs/kanon/issues/968), which holds each run's link and measured values. In short: items 1 to 4, 6 to 13 and 15 to 18 hold. Item 5 doesn't: the organisation ran at most 8 jobs at once (7 most of the time) against GitHub's documented 20 for the free plan, so the runner sizes its parallel jobs from the measured value. Item 14 doesn't either: Administration (write) without Workflows or Contents write could still make a login an admin and switch the default branch, so the `kanon` job holds no write permission at all (Kanon plan 0012, decision 23 (b)). Item 19, measured at `candidate-v0.41.0`, left one check `unchecked`, `secrets`, against probe 09's none: the read-only token can't list the repository's secret names, and doctor exited 4 (`incomplete`).

## What a probe's answer changes

From #968: a failed probe 1 stops the project; probe 7 reopens decision 9 before Issue H; probe 13 reopens decision 18 before Issue M; probe 14 or 15 reopens decisions 22 and 23 before Issue F. Every other item's "if it doesn't hold" is in §12's table, except item 19's, which §12 doesn't list: its `secrets` is why a scenario that runs `kanon.doctor` in a `kanon` segment allows exactly `secrets` unchecked and expects exit 4 ([`scenarios/README.md`](../scenarios/README.md)).
